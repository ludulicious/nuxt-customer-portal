Customer Portal uses **layer** for the code and packaging boundary and **module** for a cohesive product area shown in the application shell. A single layer can contribute one or more modules.

## Platform layers

These layers form the reusable portal foundation:

| Layer | Responsibility |
| --- | --- |
| `portal-core` | Shell, sessions, active organization, authorization, database adapters, feature registry, and dashboard |
| `authentication` | Login, registration, email verification, and password recovery |
| `account-organizations` | Account settings, memberships, invitations, and organization management |
| `administration` | System-level user and organization administration |
| `public-site` | Public home, blog, contact page, content, and assets |

[Understand the platform-layer boundaries](/modules/platform-layers)

## Business feature layers

### Timesheets

The largest current feature is a production workflow for time entry and invoicing. It contributes two user-facing modules:

- **Timesheets** — entry, timers, projects, rates, internal approvals, client approvals, supplier workflows, and reporting.
- **Invoices** — sales invoices, received invoices, attachments, PDFs, email delivery, reminders, and payment records.

[Explore timesheets and invoices](/modules/timesheets-invoices)

### Service requests

The service-request layer is a smaller reference implementation. It demonstrates tenant-scoped APIs, role policies, navigation, a module menu, dashboard widgets, translations, tests, and feature-owned database objects without the breadth of the timesheets domain.

[Explore service requests](/modules/service-requests)

## Choosing a reference

Start with service requests when you are learning the extension points or building a small workflow. Study timesheets when you need examples of a mature domain, multiple module contributions, complex approvals, client access, reporting, document generation, or email delivery.
