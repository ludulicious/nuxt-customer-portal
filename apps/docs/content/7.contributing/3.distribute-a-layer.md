title: Share and maintain a module
description: Maintain a source module in the workspace or share its code with another project.

Official modules are source code in packages/<id>, declared as private pnpm workspaces. Add the module to the main application's dependencies and portal.config.ts, then run pnpm install to update the lockfile. Its Nuxt layer entry point is nuxt.config.ts; expose shared contracts through explicit workspace exports.

There is no official npm distribution path. Share a module through a repository contribution or copy its source into a fork. A separately hosted source module must document its required contracts and migrations; supporting a different package manager is the fork maintainer's responsibility.

Keep ownership clear: routes, API handlers, translations, schema and migrations belong to the module. Cross-organization requests are rejected by server authorization, not merely hidden by the UI. Optional modules must work without unrelated optional modules. Test role and tenant boundaries, migration ordering and application integration before proposing a contribution.

See [Create a feature layer](/contributing/create-a-layer), [testing](/contributing/testing), and [compatibility and releases](/reference/compatibility-and-releases).
