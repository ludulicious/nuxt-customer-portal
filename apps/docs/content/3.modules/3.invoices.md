`@nuxt-customer-portal/invoices` works without Timesheets. It owns `/invoices`, `/admin/invoices`, `/api/invoices`, sender and banking settings, numbering, VAT defaults, billing contacts, client access and viewers, PDFs, attachments, email deliveries, payments, and invoice history in the `invoices` PostgreSQL schema.

Provider administrators may create free-form invoices for any active generic client. A client sees received invoices only while its `invoices` client module is enabled. Invoice creation never silently enables that module.

The `invoice-timesheets` integration is published as `@nuxt-customer-portal/invoice-timesheets`. Install it to add **Create from timesheets**. The option appears only when the active provider's Timesheets workspace is enabled; the selected client's Timesheets toggle does not gate it. The bridge validates approval, billability, captured rates, currency, grouping, duplicate use, and reopen protection atomically.

See [Create and manage invoices](/guides/invoicing) for the product workflow.

## Recurring invoices

Administrators can manage **Recurring invoices** from the Invoices menu. Choose a daily, weekly, monthly, quarterly or yearly period, a first invoice date, optional inclusive last invoice date, timezone and payment term. Each planned occurrence creates a draft for review; it does not issue or send the invoice.

Description, notes and item descriptions accept `{{period}}`, `{{month}}`, `{{year}}`, `{{week}}`, `{{week_year}}`, `{{period_start}}` and `{{period_end}}`. Month names follow the selected English/Dutch language; week numbers use ISO weeks and week years. Examples include `December 2026` and `Week 52 2026`. The editor previews the next invoice text.

For billing in arrears, use `{{previous_period}}`, `{{previous_month}}`, `{{previous_year}}`, `{{previous_week}}`, `{{previous_week_year}}`, `{{previous_period_start}}` and `{{previous_period_end}}`. For example, a monthly draft dated November 1, 2026 with `Hosting {{previous_period}}` renders `Hosting October 2026`; its previous service period is October 1–31. The previous period follows the schedule's recurrence anchor and ends the day before the planned invoice date, even for the first invoice. These placeholders do not change the invoice or due date.

Pausing a schedule stops generation. Resuming it, choosing a past start date or recovering from downtime catches up all missed dates in the same scheduler run, in chronological order. Future invoices are not created early. End-of-month schedules keep the original day where possible. After the first draft, start date, period and timezone are fixed; create a new schedule to change these. End dates and template text remain editable, without changing existing invoices.

The `invoices:recurring` Nitro task must run every minute. On deployments without Nitro scheduled-task support, configure an external scheduler to invoke it. Apply package migrations before enabling this task. Each run selects up to 50 schedules and processes all due occurrences for each. Drafts are individually transactionally retry-safe: failures preserve earlier drafts and resume at the failed occurrence next time. Monitor errors in the recurring invoice list; disabled invoice settings suspend processing.
