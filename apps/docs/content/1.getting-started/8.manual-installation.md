Use the [installation guide](/getting-started/installation) for the supported source and Docker paths. This page describes operational commands, not a separate installation method.

## Environment and migrations

Repository commands load apps/saas-portal/.env without overriding deployment-injected variables. Generate a unique authentication secret, for example with `openssl rand -base64 32`, and configure `BETTER_AUTH_SECRET=<paste-the-generated-secret>`. Generate PORTAL_ENCRYPTION_KEY separately with `node:crypto` and `randomBytes(32).toString('base64')`. Keep the configured public origin and Better Auth origin identical.

```sh
pnpm db:doctor
pnpm db:status
pnpm db:migrate
```

## Prepare a verified administrator

The browser signup path requires working email delivery. To prepare a verified owner before email is configured, use the repository operation against your own database:

```sh
pnpm portal provider seed --organization-name "My Portal" --organization-slug my-portal --user-name "Portal Owner" --user-email owner@example.com --user-password "your-unique-long-password"
pnpm portal admin grant --email owner@example.com
pnpm dev
```

Replace the password; avoid keeping real secrets in shell history. Seeding an existing user does not reset their password. Use the same provider slug as your existing provider. Sign in at http://localhost:3052/login and complete onboarding. Use the reserved ADMIN_EMAILS address for a new administrator.

## Docker operations

The image contains the same operational scripts. After configuring the service, execute commands inside its running container:

```sh
docker compose exec portal node /app/scripts/portal.mjs doctor
docker compose exec portal node /app/scripts/portal.mjs db status
docker compose exec portal node /app/scripts/portal.mjs admin grant --email owner@example.com
```

## Existing databases

Do not seed demo data or reinitialize a real installation. Review [database migrations](/architecture/database-migrations) before using db adopt-legacy or clients migrate. Keep backups and apply immutable migration histories from the same source revision as the running app.
