There are two supported installation paths: clone the application source or use its Docker image. All modules ship with the application. pnpm is the only supported package manager; fork the project to use another one.

## Clone the source

Requirements: Node.js 22.19 or newer on a supported Nuxt-compatible LTS release, pnpm 10.30.2, and PostgreSQL 16. Docker Compose can supply the local database.

```sh
git clone https://github.com/ludulicious/nuxt-customer-portal.git
cd nuxt-customer-portal
corepack enable
pnpm install --frozen-lockfile
cp apps/saas-portal/.env.example apps/saas-portal/.env
```

Run all following pnpm commands from the repository root. Keep pnpm at the version pinned in package.json.

### Prepare PostgreSQL

Use an empty PostgreSQL database. To start the included local database service, choose a unique URL-safe password and set POSTGRES_PASSWORD in your shell, then run:

```sh
docker compose -f compose.database.yaml up -d
```

This database listens on localhost:55432. Put the matching URL in apps/saas-portal/.env:

```dotenv
DATABASE_URL=postgresql://portal:your-url-safe-password@localhost:55432/portal
```

Alternatively use your PostgreSQL provider's URL, preserving any TLS options and percent-encoding special characters in credentials. Never commit .env files.

### Configure the application

Generate separate secrets:

```sh
node -e "console.log(require('node:crypto').randomBytes(32).toString('base64'))"
node -e "console.log(require('node:crypto').randomBytes(32).toString('base64'))"
```

Use the first as BETTER_AUTH_SECRET and the second as PORTAL_ENCRYPTION_KEY. Set PUBLIC_URL and BETTER_AUTH_URL to http://localhost:3052 for local development. Set ADMIN_EMAILS to your administrator email, and choose PORTAL_PROVIDER_NAME and PORTAL_PROVIDER_SLUG.

```sh
pnpm db:doctor
pnpm db:status
pnpm db:migrate
pnpm portal provider bootstrap --organization-name "My Portal" --organization-slug my-portal
pnpm dev
```

Open http://localhost:3052/signup. The initial administrator must use the reserved ADMIN_EMAILS address. Configure [email delivery](/getting-started/usage#email-delivery) to verify the account, or use [manual administrator setup](/getting-started/manual-installation) to create a verified administrator before email is available. Complete browser onboarding for branding, languages, modules and legal content.

Follow [your first workflow](/getting-started/first-workflow) after setup. Modules are configured in the browser; code composition is in apps/saas-portal/portal.config.ts.

## Run the Docker image

You need Docker Compose and the repository's compose.yaml and .env.example files, or equivalent deployment configuration. No Node.js or pnpm installation is required on the host.

Copy .env.example to .env, replace all secrets, set ADMIN_EMAILS, and set PORTAL_IMAGE to a verified release tag or immutable digest. Use URL-safe characters for POSTGRES_PASSWORD because Compose places it in DATABASE_URL.

```sh
docker compose up -d
```

Open http://localhost:3052/signup and complete administrator setup. The entrypoint applies pending migrations and bootstraps the provider. Data and uploaded files persist in volumes. See [deployment](/getting-started/deployment) for production configuration, operational commands and backups.

## Upgrade

Back up PostgreSQL and file storage first. Source installations update the repository checkout and run pnpm install --frozen-lockfile, migrations and build. Docker installations update the pinned image reference and recreate the portal container. Read the product changelog and [upgrade recovery](/operations/upgrade-recovery).
