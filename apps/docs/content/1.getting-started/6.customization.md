apps/saas-portal is the application you customize. Complete onboarding and use Portal settings to configure branding, appearance, languages, client types, modules, support and legal content. Changes are stored in PostgreSQL and apply at runtime. Demo deployments expose these settings read-only.

## Edit the host

The host owns app/app.vue, app/assets/css/main.css, public assets, translations and Nuxt configuration. Add host components, layouts or route overrides under apps/saas-portal/app/. Reuse neutral UI primitives from packages/ui and capability contracts from packages/core.

To customize a layer page, copy its source directly to the matching path under apps/saas-portal/app/pages/ and declare any new direct dependencies in the app manifest. Nuxt gives host pages precedence over layer pages. Review upstream changes to overridden files during upgrades; there is no page-copy installer command.

Examples: the login route source is packages/authentication/app/pages/login.vue, legal routes live in packages/saas-configuration/app/pages/, and the shared shell is in packages/ui/app/layouts/. The main application is the canonical example; alternate Apex and Brutal apps have been removed. Existing appearance code remains in the configuration module.

## Edit or add a module

Module code lives in packages/<id>. Keep pages, APIs, translations and migrations together. Compose source modules in apps/saas-portal/portal.config.ts and declare workspace dependencies in its package.json. Browser module settings control availability; removing a code module requires reviewing integration dependencies and preserving its data.

Follow [Create a feature layer](/contributing/create-a-layer) and [feature contracts](/reference/feature-contract). Keep branding in the host, use Nuxt UI forms with Zod and novalidate, and authorize all server operations. Source customization requires rebuilding; Docker users who customize code build their own image from the checkout.
