Nuxt Customer Portal is one application with separate code modules. apps/saas-portal owns the host, branding, runtime configuration and deployment. apps/docs is the documentation website. There are no alternate portal apps or generated hosts.

## Code boundaries

Each private pnpm workspace under packages/ owns a capability. Core supplies sessions, authorization, tenancy, database access and feature contracts. UI supplies neutral layouts, navigation and shared controls. Authentication, organizations, administration and clients supply platform workflows. Business modules own their pages, APIs, translations and immutable SQL migrations.

Cross-module imports use the existing @nuxt-customer-portal/... workspace exports. These names are internal source contracts, not npm installation instructions. Modules do not import application files or depend on optional business modules unless they are explicit integration modules.

apps/saas-portal/portal.config.ts composes the modules. Browser settings control enabled capabilities without downloading code. See [Nuxt layers](/architecture/layers) and [feature contracts](/reference/feature-contract).

## Operations and demo

scripts/portal.mjs provides diagnostics, migrations, provider/admin operations and Harvest import. Its configuration helpers live in core; operational database code stays in scripts/portal/. Docker startup uses those same operations.

The integrated layer at apps/saas-portal/layers/demo supplies anonymous demo sessions, fixtures and daily resets. It runs only when explicitly enabled on its own database. Production and demo deployments use the same app/image. Demo settings are read-only; per-visitor settings are deferred.

## Distribution

Install by cloning the repository or using the Docker image. pnpm is the only supported package manager. Modules remain separate for maintenance and extension, and ship with one product version. See the [source map](/reference/source-map).
